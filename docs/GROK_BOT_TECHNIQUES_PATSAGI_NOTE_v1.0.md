## Ranked Techniques (highest leverage first)

1. **Explicit constraint markers + dual-repo pointers**  
   Every note or draft must state what it is *not* allowed to change (inspectable research posture, AG-SML terms, no public key proxy, no new technical claims). Point to the canonical source in the Ra-Thor monorepo and the surface file in Powrush-MMO (or Ra-Thor-Comic). Prevents drift on rewake.

2. **List-first public copy**  
   When presenting multiple facts, benefits, or features on rathor.ai, powrush.com, or series materials, use numbered or bulleted lists instead of dense paragraphs. Improves scannability without altering substance. See `docs/COPYWRITING_LISTS_PATSAGI_NOTE_v1.0.md`. Human review required before live updates.

3. **Cross-link and status headers**  
   Start every new or updated doc with a short status block (date, contact, license, related files). Add a one-line pointer in the nearest existing entry-point file (VISION.md, FACTIONS_OVERVIEW.md, series seed, etc.). Lets bots discover related work without root walks.

4. **Inspirational vs. operational separation**  
   Mark narrative, lore, or marketing colour as inspirational only. Keep technical, licensing, and architectural files free of it. Bots may extend the inspirational layer; they must not fold it into claims about code, physics, or product readiness.

5. **Ready-to-reference seed files**  
   Prefer short, self-contained Markdown notes (core motif, mapping to existing systems, constraints, example surfaces) that a bot can load and apply. Longer series bibles or full rewrites stay human-gated.
