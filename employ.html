Run your organization’s own governed bot team

Inspectable research software with Mercy-Checks: a small team of bots you run on your repo, not a hosted agent farm. Organizations can ask about this through info@Rathor.ai.

A lead bot receives each card, keeps scope honest, and routes work to the right council seat.

Three council seats

  • Reviewer — votes on the change itself: scope, honesty, and wording.
  • Paths — votes on which files and paths the change touches, proving it stays in scope.
  • Core — votes on runtime, workflows, service worker, manifest, keys, security, public API, and public AI-read text.

Mercy-Checks merge

Nothing lands without the Mercy-Ways process:

  1. 1. One draft PR from the tip of main.
  2. 2. Green CI on the exact PR head.
  3. 3. Each seat posts its vote on that exact head SHA.
  4. 4. Any new push voids the votes — seats vote again.
  5. 5. Squash merge pinned to that SHA.
  6. 6. A live check that the change is really on the site.

Owner-only (human, always): payments, publishing, pricing, outreach, new public claims, and locked files.

Honesty line: no fake approvals or scores. Gaps are flagged, never filled in.

Coordination runs through GitHub — PRs, one council-board issue, and direct bot-to-bot messages when a seat needs a handoff.

Five-step setup

  1. 1. Create a lead bot for your organization.
  2. 2. Add the three seat bots (Reviewer, Paths, Core).
  3. 3. Connect GitHub with the permissions your merge process needs.
  4. 4. Name one council-board issue for stall flags and HOLD notes.
  5. 5. Turn on an hourly stall watchdog (flags only — it never merges, reverts, or pushes).
